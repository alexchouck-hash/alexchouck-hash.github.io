Where AI actually helps, and where it will embarrass you.

Task-by-task guides for device engineers. Each one names what AI does well, shows a worked example on synthetic data, and is explicit about what it gets wrong — because the failures are the part nobody publishes.

How these are written

Every guide follows the same shape, because the shape is the argument:

  • The task, stated as an engineer would state it.
  • Where AI helps, and where it fails — with the failure named specifically, not hedged.
  • Prompt patterns that work, and why.
  • A worked example on synthetic data. Never a real device, never a client's file.
  • A verification checklist, because the output is a draft.
  • What never to delegate — the judgements that stay yours.

Nothing in these guides produces a DHF-ready document. AI drafts; a named engineer decides and signs. A guide that blurred that line would be teaching the habit that gets a file cited.
